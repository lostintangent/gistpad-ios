# GistPadInterface

Native Library and note-screen chrome for iOS 27.1 and later. Screen inputs are Sendable value types. The app owns navigation, authentication, editor sessions, rendering and persistence. This package never initiates a network write. Visual rules and review requirements belong to [the design system](../../docs/design-system.md) and [design direction](../../docs/design-direction.md).

`PersonalAccentColorRow(savedHex:hasInvalidStoredValue:save:)` uses an opaque native color picker and an explicit async Save action. Supply an account-scoped callback so a pending selection cannot save to a switched account. Failures stay visible and retain the chosen color. Invalid saved metadata shows a warning rather than silently claiming it was valid. Apply `.personalAccent(savedHex:)` above the workspace and its sheets to share the same contrast-derived accent through SwiftUI, UIKit and preview content.

Personal color belongs to content, not navigation or commands. Apply the accent environment, not an app-wide tint. Appearance resolves contrast-derived roles for SwiftUI, UIKit and Preview. Role derivation stays internal to Appearance.

`LibraryView(model:actions:footer:isTodaySelected:isSidebar:expandedCollections:pinnedExpanded:)` belongs in the sidebar of a `NavigationSplitView`. Home is always titled GistPad, without Today, Pinned or Your Gists headings. Pinned is the first section of ordinary rows, sorted by last update with no pin position, and starts expanded. In the regular sidebar the Library uses the system sidebar list style, so Pinned is a native collapsible section with its own disclosure chevron, bound to `pinnedExpanded`; bind it to account-local preferences, or omit it for local presentation state. In compact width the Library uses `.insetGrouped`, which draws no disclosure chevron, so Pinned is a non-collapsible section there and ignores `pinnedExpanded`. Pinned, date-group and collection headers are plain text in the default header type and color, with no symbols. Headers, including the Daily Notes, Starred and Archived headers, keep the system header inset in both widths. Date groups follow: Today, Yesterday, Previous 7 Days and Previous 30 Days, then months of the current year and earlier years. Undated notes form a trailing section without a header. Empty groups never render, and date groups do not collapse. Search reveals matching pinned notes temporarily without writing the preference. Section headers use the system List rhythm rather than a custom pitch or transition. Pinned and dated rows keep native List selection, context menus and swipes; Search results do too. Folded Home has New, Today and Settings above, with Tags below. The regular sidebar retains Tags and Settings in its overflow menu. Commands stay neutral.

Apply `.libraryRail(isVisible:today:isTodaySelected:create:openToday:)` to regular detail content so New and Today appear together without duplicate sidebar controls. Apply `.librarySearch(model:isPresented:isSidebar:)` to the split root. Supply the same `isSidebar` from the split container's environment to the Library and its search modifier. Search retains the shipped native presentation ownership and text interaction.

Bind the active document to `LibraryModel.selectedNoteID`. Apply snapshots without recreating the model so search and AND-combined tag filters survive updates. An invisible or collapsed row leaves its document open with no selected Library row, not an extra shelf. Owned starred gists can appear in main and Starred, with only the chosen occurrence selected. Native nil List selection never clears the retained document. The optional diagnostic footer shares the outer scroll.

Set `LibraryNote.gistID` to the actual published identity, including search file rows. Leave it nil for unpublished drafts and recovery copies. `mainGistCount` and Starred/Archive counts deduplicate published gist IDs. The main total remains in the GistPad subtitle through filtering. Supply `LibrarySnapshot.dailyNoteCount` as an optional unfiltered actual-day count, including local-only days. Unknown totals stay absent, not zero. Use `replaceSnapshot(_:)` with confirmed remote/cached values, or nil when the snapshot is unknown.

Daily Notes, Starred Gists and Archived Gists are native disclosures after the date groups, in that order, with actual unfiltered membership. Each target retains its full title and bare localized count in adaptive primary ink. They start collapsed. The List owns the row minimum, while ordinary rows keep their intrinsic density. At accessibility sizes, the title wraps beside the count, the decorative symbol yields and native content insets grow the row. Empty sections, including known zero totals, never render, even when previously expanded. Rows with an unknown total retain the title without inventing a count. Bind `expandedCollections` to account-local preferences, or omit it for local presentation state. Search temporarily reveals matching collections without writing remembered choices. Clearing filters restores them. All groups share one outer List, with no capped inner scroll.

Set optional `LibraryActions.select` to prepare a document synchronously before navigation. It receives non-nil row IDs and owns updating `selectedNoteID`. Otherwise the Library writes directly to the model. Explicitly clear or replace that identity only when leaving or switching the document.

Set `LibraryNote.canDeleteFromGitHub` only for a published gist owned by the account, never for unpublished or recovery copies. Owned notes that are published or local-only (`LibraryNote.isLocalOnly`: no gist ID or a recovery copy) and have `LibraryActions.delete` offer isolated destructive Delete in their context menu, so every owned note can be removed in any state. Owned rows offer red trailing Delete beside Archive, and leading Pin or Unpin, with the same actions in their context menu. Pinned rows behave identically. The callback receives the row ID so the app can resolve search/file rows to their owning gist. Return `LibraryActions.deletionConfirmation` with that exact row ID, the owning gist's title and account-scoped confirm/dismiss callbacks. The native GitHub confirmation belongs to the target row, so its popover never points at another gist. The row swipe deliberately has no destructive role until confirmation, so cancelling cannot optimistically remove the row.

For app-owned full-text/tag-token search, set `LibraryModel.searchState` to `.searching`, `.results(notes:coverage:)` or `.failed(message:)`. One all-collection result is grouped without a second title or tag filter. Overlapping results appear once in their primary collection. Daily rows use overdue/date order, while ordinary result order is preserved. The app owns row-to-document/file/draft resolution and invalidates results when the query changes. Coverage remains model data, not Library prose. The only summary is "Matches all selected tags" when multiple tags are selected. Text-only and single-tag searches reserve no summary section or spacing. Failed or pending search never silently falls back to title-only filtering.

`LibraryModel.today` supplies the exact current-day availability and optional real task progress. `LibraryTodayButton` is one native calendar action with a badge only for positive known unfinished tasks from an existing day. Counts above 99 show `99+`, while accessibility retains the full localized count. Unknown, missing and zero counts have no badge. Presentation never fetches, creates or publishes. The app's explicit action uses its shared ensure path and enters Edit with the keyboard, while automatic no-selection restoration stays quiet. Set `isTodaySelected` only for the exact current-day file or its opening state. A date rollover changes the destination and badge, not the open document.

`LibraryNoteRow` renders supplied metadata and at most two tags with honest overflow. Dates show local time today, Yesterday, the weekday this calendar week, then a short date with a year only when needed. A minute timeline updates day boundaries. Supply `LibraryNote.dailyDate` from the verified Daily filename parser for localized date titles and full spoken dates, without duplicated modification time, filename or file count.

Rows expose real task progress, overdue meaning, publication state and ownership visually and to accessibility. Layout responds to available width and Dynamic Type without shrinking type or capping row height.

Compact Home uses an always-visible `UISearchBar` in a bottom `safeAreaBar`, sharing the regular sidebar's query and presentation binding. UIKit owns typing, in-field Clear, submission and keyboard avoidance. There is no separate Cancel button. Clear empties the query without dismissing the focused field. Keyboard Search or scrolling results dismisses the keyboard while preserving the query and results. Losing focus with an empty query ends text search without clearing independently selected tags. Regular Search uses `.sidebar` placement and `DefaultToolbarItem(kind: .search, placement: .bottomBar)`, retaining its system-owned dismissal controls because SwiftUI exposes no supported Cancel-visibility API. Routine background checks never replace Search.

Compact Search measures usable content and window widths to account for a native side-toolbar reservation, excluding hardware safe areas and subpoint rounding. Horizontal toolbars retain their bottom inset. Empty placeholders truncate within the capsule without shrinking, while queries retain native clear and text scrolling. The DEBUG host's `--capture-horizontal-toolbar` exercises the alternate native arrangement.

`GitHubStatusControl(state:recover:)` belongs in a conditional trailing `.bottomBar` item with a flexible spacer and `.sharedBackgroundVisibility(.hidden)`. Apply `.gitHubStatusKeyboardPolicy()` at the stable scene root and gate the item with `isGitHubStatusVisible`. This hides the covered item during typing without changing its model. Checking is delayed 350 ms and cancelled when the operation ends. `GitHubStatusProblem` carries the verified reason, safety detail, recovery action and optional server deadline. The owner retains problems through recovery and clears them only on success. Set `LibraryModel.gitHubStatus` and `LibraryActions.recoverStatus` from the app's read policy. First-load and save-safety failures remain explicit, separate recovery paths.

`TagLabel` and `TagLabels` preserve full names, wrap at available width and announce the complete tag set even when a visible limit applies. A saved color fills its label at full opacity, with black or white text chosen by higher contrast, which reaches at least 4.5:1 for every saved color. A missing color uses a neutral system fill with primary text. Near-white and near-black fills gain a hairline separator edge. Untagged rows reserve no space. `NoteChrome.tags` exposes gist-level tags through the Tags route.

`TagEditor(tags:selectedTagIDs:save:)` presents one native searchable list without a duplicate selected-chip panel. Swipe, context menu and a named accessibility action expose tag editing. Omit `save` for nonmutating tags. This capability is independent of GitHub source access: a signed-in profile can tag an associated read-only or truncated gist. Editable selections, new UUID-backed tags, rename/color and confirmed global deletions stay in the sheet until Save. The async callback receives idempotent `TagEdit` operations in dependency order: upsert, membership, deletion. Apply them against fresh account metadata, preserve unrelated fields, and throw useful non-sensitive failures. Retry retains every local choice and stable ID. An attempt journal also reconciles choices edited after a partially applied failure. Closing never promises to undo remote changes. A save dismisses the sheet only after the callback succeeds. No callback is invoked when nothing changed.

`NoteScreen(document:mode:saveState:actions:source:preview:)` belongs in detail navigation. Supply the retained editor and Preview. `allowsSplit` gates the Edit/Split/Preview control, while `AnyLayout` keeps both children mounted through mode changes. A split preference displays source at insufficient width without rewriting its binding. The app owns mode preference and sidebar visibility. `isSidebarHidden` supplies the Show/Hide Library label, not another navigation root. `NoteAccess` blocks editing incomplete or read-only data.

Published, non-Daily notes can supply `NoteActions.comments`, `areCommentsPresented` and a known `NoteChrome.commentCount` for the native toolbar toggle and passive total. `NoteCommentsLabel` composes the symbol and count into one original-rendering image, preserving native adaptive toolbar placement and centering the bubble on the other rail glyphs. The count uses primary foreground fill, inverse digits and a thin system-background ring so it remains distinct on the selected button. The bubble itself inverts when selected. Unknown and zero totals omit the count, while totals above 99 show `99+`. VoiceOver retains the full known total. `LibraryNote.commentCount` adds a quiet bubble/count only for positive known totals, with a separate trailing line at accessibility sizes. `LibraryActions.openComments` exposes the same native context-menu and accessibility action. Counts never initiate a fetch.

`CommentsConversation` renders gist-wide GitHub threads with native inline Markdown text, author/date context, two reply levels, verified per-surface quote destinations and permission-aware actions. Its native scrolling stack keeps recursive DisclosureGroups independent, avoiding a parent List cell handling a nested disclosure's action. Selected roots retain one inset neutral surface for their replies, a small accent marker beside the author and the accessibility selected trait. Reply and quote expansion are neutral native bordered controls with wrapping labels and 44-point targets. Host the composer in `safeAreaBar` so the conversation's native soft bottom edge extends behind it. Unknown, confirmed empty, refresh and failure remain distinct. `selectedRootRevision` explicitly reveals an already-selected thread again. `CommentsComposer` owns only growing native text entry, captured context and explicit Send. The app supplies validated edit/post capabilities, draft persistence, operation errors and deliberate focus requests. It must flush before closing and keep failed saves visible. No comment is posted by leaving the field, inspector or app. The native inspector hosts Comments only. Review remains in Intelligence, and no offline thread cache is implied.

Provide only supported `NoteActions`. Unavailable optional actions are absent, not dead controls. `didChangeMode` lets the document owner manage its text view's responder status when the user deliberately switches source/preview. A layout or posture change never triggers that callback. Multi-file notes retain the native title-menu chevron, but omit the subtitle when the selected filename is README.md, case-insensitively. Other exact filenames have a body-scaled 4-point top inset in the supported native subtitle view. Single-file notes retain one title line. The title menu lists every exact filename directly, with a check beside `selectedFileID`. When the app supplies `NoteFile.date` from its shared filename-format detection, dated files group by Gregorian year/month, newest first. The menu keeps README and other undated files directly visible and never guesses dates from names. File selection invokes `selectFile`; the app owns completing the switch and updating the selection. The toolbar's Files menu offers the same choices without an intermediate sheet. Files remains available for a single-file gist when `addFile` or `renameFile` is supported, with those actions after a divider. Preserve selection, composition, undo and drafts at that boundary.

`NoteSaveState` owns save notices, recovery classification and publish capability. Healthy states create no footer, `.offline` exposes a toolbar explanation, and failures retain a notice with optional Details. Supply the **effective** `NoteChrome.isAutoSaveEnabled`, false while conflict review requires deliberate publication. Healthy autosave hides manual Save, failed publication restores it, and `canPublish` still gates the action.

Problem notices use the system `safeAreaBar`, extending the native scroll-edge effect. The injected editor and preview own their underlap: measure vertical safe-area insets before extending their native representable under container edges, and bridge the measured insets to its scroll view without doubling UIKit's contribution. NoteScreen does not suppress those insets or keyboard avoidance. Do not add an opaque footer background, duplicate bottom padding, or a web/CSS fade. Verify the final document line and source caret remain reachable above the bar and keyboard. The note's native actions menu uses a compact Pin/Star/Share/Copy group, content/view actions including optional `find`, Open in GitHub, Archive and isolated Delete.

Save labels are assertions about real persistence. In-memory and unsaved states do not claim a local write. Only a confirmed matching remote version is `.savedToGitHub`. Failure messages must be useful, non-sensitive user-facing explanations. Supply retry/review callbacks for recoverable failures. Share callbacks own the unsaved-version choice and secret-link disclosure before presenting the native share sheet.

`PhotoPrivacyNotice(proceed:cancel:)` explains public image storage before the first pick, including for secret gists. Omit `proceed` to show the same notice as help. The app owns per-account acknowledgement and PhotosPicker, without broad library access. Place `PhotoAttachmentShelf(attachments:maximumHeight:details:)` above the existing save status in source/preview. It is a bounded disclosure summary at every text size, with count and failure status, not an inline scrolling list. The app dismisses source input before presenting `PhotoAttachmentDetails(attachments:action:remove:)`, whose large native sheet contains the full scrollable rows and neutral controls. Preparing, local durability, waiting for a published note, transfer, uncertainty, reconnect, upload failure and failed local insertion remain distinct. Only a verified upload can offer Insert Here. Retry honors its exact server deadline. Removal requests require an app-owned confirmation and never imply remote deletion. These components do not upload, insert source or claim an Undo transaction.

Disclosure and recovery use one native `UIButton` target each, with scaled SwiftUI labels in `UIHostingConfiguration`. The label is not a second accessibility element. Native enabled/highlighted states and primary actions belong to the control, while the SwiftUI label retains the adaptive summary and neutral primary ink.

Identical failure explanations share one section footer instead of repeating in every row. Sections follow the first matching photo and retain photo order within each reason. Distinct explanations remain with their photos. Progress/status and detail/guidance use semantic secondary ink without additional opacity, and recovery stays neutral primary. The compact issue symbol is filled, while accessibility retains the exact failure count.
