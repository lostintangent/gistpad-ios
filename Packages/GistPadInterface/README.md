# GistPadInterface

Native Library and note-screen chrome for iOS 27.1 and later. Screen inputs are Sendable value types. The app owns navigation, authentication, editor sessions, rendering and persistence. This package never initiates a network write.

`PersonalAccentColorRow(savedHex:hasInvalidStoredValue:save:)` uses an opaque native color picker and an explicit async Save action. Supply an account-scoped callback so a pending selection cannot save to a switched account. Failures stay visible and retain the chosen color. Invalid saved metadata shows a warning rather than silently claiming it was valid. Apply `.personalAccent(savedHex:)` above the workspace and its sheets to share the same contrast-derived accent through SwiftUI, UIKit and preview content.

`LibraryView(model:actions:footer:isTodaySelected:isSidebar:)` belongs in the sidebar of a `NavigationSplitView`. The compact Library uses a semantic grouped canvas, a date-led Today feature, distinct Pinned content and a separated inset-grouped Notes list. Pinned cards adapt to available space, with a minimum 156-point card and 12-point gaps. Accessibility sizes, narrow containers and sidebars use featured rows instead. Card heights follow their content. A native title menu selects All Notes, Daily Notes, Starred and Archive. Apply `.librarySearch(model:isPresented:)` to the split root so native sidebar placement belongs to the whole navigation container, with Library's `DefaultToolbarItem` identifying its compact search column. The optional presentation binding activates the native field and its keyboard. Standalone Library hosts retain their own searchable presentation. Both boundaries apply the shared personal tint. Supply `isSidebar` from the split container's environment when its child column receives a narrower size class. Selection-bound sidebar rows retain the native selected-row shape.

Bind the app's active document to `LibraryModel.selectedNoteID`. Apply `LibrarySnapshot` values without recreating the model so collection, search and AND-combined tag filters survive updates. Only the default unfiltered Library features pinned notes, once. Search and other collections use one ordinary result list with pin indications. Excerpts and file counts appear only when supplied. A selected note that stops matching remains in Open document until selection changes. Load failures and cached offline content are explicit states. Empty collections explain their purpose, while the signed-out and empty-notebook invitations use GistPad's original artwork. The optional diagnostic footer scrolls with the list.

Set optional `LibraryActions.select` when the app must prepare the selected document synchronously before navigation. It receives non-nil row selections and owns updating `selectedNoteID`. Without it, selection writes directly to the model. Clearing selection still writes nil directly.

For app-owned full-text/tag-token search, set `LibraryModel.searchState` to `.searching`, `.results(notes:coverage:)` or `.failed(message:)`. Supplied result row IDs and ordering pass through without a second title, collection or tag filter. The app owns row-to-document/file/draft resolution and invalidates results when the query changes. Coverage is one unboxed secondary caption above results or the empty state, preserving incomplete-file and older-cache warnings. A scope card appears only for selected tags or a nondefault collection, and the AND explanation appears only with multiple tags. A failed or pending search never silently falls back to the title-only filter.

`LibraryModel.today` supplies a pinned date/time zone and optional real task progress. Unknown progress is omitted, not displayed as zero. `TodayLanding(summary:start:)` is the unselected detail when no existing note is available. It never creates anything on appearance. The app performs creation only in `start`, and owns restoring the last account-scoped note/file before choosing this fallback. The navigation sidebar uses one compact Today destination instead of duplicating the feature and Start invitation. Set `isTodaySelected` when that detail is visible.

`TagLabel` and `TagLabels` share primary-text names, a color dot and an opaque softly tinted surface. Labels wrap at available width and retain full names at large type. Ordinary Library rows place the date, up to two compact labels, overflow count and known file count in one wrapping metadata group. Pinned content retains its separate labels. `NoteChrome.tags` exposes all gist-level tags through one labeled Tags route without a ribbon over the writing canvas. Small metadata uses semantic text styles rather than arbitrary low-contrast opacity.

`TagEditor(tags:selectedTagIDs:save:)` combines the complete wrapping group with a native searchable picker. Swipe, context menu and a named accessibility action expose tag editing. Omit `save` for nonmutating tags. This capability is independent of GitHub source access: a signed-in profile can tag an associated read-only or truncated gist. Editable selections, new UUID-backed tags, rename/color and confirmed global deletions stay in the sheet until Done. The async callback receives idempotent `TagEdit` operations in dependency order: upsert, membership, deletion. Apply them against fresh account metadata, preserve unrelated fields, and throw useful non-sensitive failures. Retry retains every local choice and stable ID. An attempt journal also reconciles choices edited after a partially applied failure. Closing never promises to undo remote changes. A save dismisses the sheet only after the callback succeeds. No callback is invoked when nothing changed.

`NoteScreen(document:mode:saveState:actions:source:preview:)` belongs inside the detail navigation container. Supply the existing source editor and preview. `NoteMode.split` and `allowsSplit` expose the native Edit/Split/Preview control. An `AnyLayout` keeps both children mounted while switching between overlaid and side-by-side placement. When width stops allowing split, a split preference displays source without rewriting the binding. The app owns per-device mode preference and sidebar visibility. Pass `isSidebarHidden` for the Show/Hide Library label, without moving into a separate navigation root. Existing notes start in `.reading`, new notes in `.source`, and interrupted sessions retain their existing mode. `NoteAccess` blocks editing incomplete or read-only data.

Provide only supported `NoteActions`. Unavailable optional actions are absent, not dead controls. `didChangeMode` lets the document owner manage its text view's responder status when the user deliberately switches source/preview. A layout or posture change never triggers that callback. The title menu lists every exact filename directly, with a check beside `selectedFileID`. When the app supplies `NoteFile.date` from its shared filename-format detection, dated files group by Gregorian year/month, newest first. The menu keeps README and other undated files directly visible and never guesses dates from names. File selection invokes `selectFile`; the app owns completing the switch and updating the selection. The toolbar's Files menu offers the same choices without an intermediate sheet. Files remains available for a single-file gist when `addFile` or `renameFile` is supported, with those actions after a divider. Preserve selection, composition, undo and drafts at that boundary.

Healthy save states create no footer. A typed `.offline` state exposes a quiet toolbar glyph with an explanation and Retry. Actual failures, conflict, reconnect and uncertain publication retain one compact notice, with diagnostics behind Details. The app supplies the **effective** `NoteChrome.isAutoSaveEnabled`, false while conflict review requires a deliberate publish. Healthy autosave hides manual Save; failed publishing restores it. The action remains gated by the true `canPublish` state.

Problem notices use the system `safeAreaBar`, extending the native scroll-edge effect. The injected editor and preview own their underlap: measure vertical safe-area insets before extending their native representable under container edges, and bridge the measured insets to its scroll view without doubling UIKit's contribution. NoteScreen does not suppress those insets or keyboard avoidance. Do not add an opaque footer background, duplicate bottom padding, or a web/CSS fade. Verify the final document line and source caret remain reachable above the bar and keyboard. The note's native actions menu uses a compact Pin/Star/Share/Copy group, content/view actions including optional `find`, Open in GitHub, Archive and isolated Delete.

Save labels are assertions about real persistence. In-memory and unsaved states do not claim a local write. Only a confirmed matching remote version is `.savedToGitHub`. Failure messages must be useful, non-sensitive user-facing explanations. Supply retry/review callbacks for recoverable failures. Share callbacks own the unsaved-version choice and secret-link disclosure before presenting the native share sheet.

`PhotoPrivacyNotice(proceed:cancel:)` explains public image storage before the first pick, including for secret gists. Omit `proceed` to show the same notice as help. The app owns per-account acknowledgement and PhotosPicker, without broad library access. Place `PhotoAttachmentShelf(attachments:maximumHeight:details:)` above the existing save status in source/preview. It is a bounded disclosure summary at every text size, with count and failure status, not an inline scrolling list. The app dismisses source input before presenting `PhotoAttachmentDetails(attachments:action:remove:)`, whose large native sheet contains the full scrollable rows and personal-accent controls. Preparing, local durability, waiting for a published note, transfer, uncertainty, reconnect, upload failure and failed local insertion remain distinct. Only a verified upload can offer Insert Here. Retry honors its exact server deadline. Removal requests require an app-owned confirmation and never imply remote deletion. These components do not upload, insert source or claim an Undo transaction.

Disclosure and recovery use one native `UIButton` target each, with scaled SwiftUI labels in `UIHostingConfiguration`. The label is not a second accessibility element. Native enabled/highlighted states and primary actions belong to the control, while the SwiftUI label retains the adaptive summary and personal-accent styling.

Identical failure explanations share one section footer instead of repeating in every row. Sections follow the first matching photo and retain photo order within each reason. Distinct explanations remain with their photos. Status stays primary, detail/guidance uses explicit semantic `secondaryLabel` without additional opacity, and each recovery retains the personal accent. The compact issue symbol is filled, while accessibility retains the exact failure count.

`InterfaceFixtures` and SwiftUI previews use synthetic data. The debug capture workspace accepts `--capture-accent #FACC15` to apply the real shared accent bridge without an account, and records the supplied accent in its readiness metadata. Use `--capture-screen library --capture-state search-active --capture-ready-token <UUID>` for actual-app active Search. Readiness requires both the query field's first responder and an onscreen keyboard frame, recorded as `searchFocused` and `searchKeyboardVisible`. It never fabricates readiness when a hardware keyboard keeps the software keyboard hidden. The native String Catalog and four-appearance color assets live in the package resource bundle. `scripts/capture-matrix.sh` and `docs/capture-matrix.md` define the shared review workflow. No screen is production-approved until Designer reviews the required Duo evidence.
