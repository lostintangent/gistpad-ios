# GistPadInterface

Native Library and note-screen chrome for iOS 27.1 and later. Screen inputs are Sendable value types. The app owns navigation, authentication, editor sessions, rendering and persistence. This package never initiates a network write.

`LibraryView(model:actions:footer:)` belongs in the sidebar of a `NavigationSplitView`. It uses a continuous reading canvas when compact and the native sidebar style as a companion column. Bind the app's active document to `LibraryModel.selectedNoteID`. Apply `LibrarySnapshot` values without recreating the model so collection, search and AND-combined tag filters survive updates. Default snapshot filtering groups pinned and recent notes separately. A selected note that stops matching remains in Open document until selection changes. Load failures and cached offline content are explicit states. The optional diagnostic footer scrolls with the list.

Set optional `LibraryActions.select` when the app must prepare the selected document synchronously before navigation. It receives non-nil row selections and owns updating `selectedNoteID`. Without it, selection writes directly to the model. Clearing selection still writes nil directly.

For app-owned full-text/tag-token search, set `LibraryModel.searchState` to `.searching`, `.results(notes:coverage:)` or `.failed(message:)`. Supplied result row IDs and ordering pass through without a second title, collection or tag filter. The app owns row-to-document/file/draft resolution and invalidates results when the query changes. Coverage distinguishes unavailable content, incomplete file lists and older cached results. A failed or pending search never silently falls back to the title-only filter.

`LibraryModel.today` supplies a pinned date/time zone and optional real task progress. Unknown progress is omitted, not displayed as zero. `TodayLanding(summary:start:)` is the unselected detail when no existing note is available. It never creates anything on appearance. The app performs creation only in `start`, and owns restoring the last account-scoped note/file before choosing this fallback.

`TagLabel` and `TagLabels` share primary-text names, a color dot and an opaque softly tinted surface. Labels wrap at available width and retain full names at large type. Library rows display two labels and a truthful overflow count. `NoteChrome.tags` exposes all gist-level tags through one labeled Tags route without a ribbon over the writing canvas. Small metadata uses primary text and typographic hierarchy rather than low-contrast opacity.

`TagEditor(tags:selectedTagIDs:save:)` combines the complete wrapping group with a native searchable picker. Swipe, context menu and a named accessibility action expose tag editing. Omit `save` for nonmutating tags. This capability is independent of GitHub source access: a signed-in profile can tag an associated read-only or truncated gist. Editable selections, new UUID-backed tags, rename/color and confirmed global deletions stay in the sheet until Done. The async callback receives idempotent `TagEdit` operations in dependency order: upsert, membership, deletion. Apply them against fresh account metadata, preserve unrelated fields, and throw useful non-sensitive failures. Retry retains every local choice and stable ID. An attempt journal also reconciles choices edited after a partially applied failure. Closing never promises to undo remote changes. A save dismisses the sheet only after the callback succeeds. No callback is invoked when nothing changed.

`NoteScreen(document:mode:saveState:actions:source:preview:)` belongs inside the detail navigation container. Supply the existing source editor and preview. `NoteMode.split` and `allowsSplit` expose the native Edit/Split/Preview control. An `AnyLayout` keeps both children mounted while switching between overlaid and side-by-side placement. When width stops allowing split, a split preference displays source without rewriting the binding. The app owns per-device mode preference and sidebar visibility. Pass `isSidebarHidden` for the Show/Hide Library label, without moving into a separate navigation root. Existing notes start in `.reading`, new notes in `.source`, and interrupted sessions retain their existing mode. `NoteAccess` blocks editing incomplete or read-only data.

Provide only supported `NoteActions`. Unavailable optional actions are absent, not dead controls. `didChangeMode` lets the document owner manage its text view's responder status when the user deliberately switches source/preview. A layout or posture change never triggers that callback. The title menu lists every exact filename directly, with a check beside `selectedFileID`. When the app supplies `NoteFile.date` from its shared filename-format detection, dated files group by Gregorian year/month, newest first. The menu keeps README and other undated files directly visible and never guesses dates from names. File selection invokes `selectFile`; the app owns completing the switch and updating the selection. The toolbar's Files menu offers the same choices without an intermediate sheet. Files remains available for a single-file gist when `addFile` or `renameFile` is supported, with those actions after a divider. Preserve selection, composition, undo and drafts at that boundary.

Healthy save states create no footer. A typed `.offline` state exposes a quiet toolbar glyph with an explanation and Retry. Actual failures, conflict, reconnect and uncertain publication retain one compact notice, with diagnostics behind Details. The app supplies the **effective** `NoteChrome.isAutoSaveEnabled`, false while conflict review requires a deliberate publish. Healthy autosave hides manual Save; failed publishing restores it. The action remains gated by the true `canPublish` state.

Problem notices use the system `safeAreaBar`, extending the native scroll-edge effect. Source and preview extend under container edges without ignoring keyboard avoidance. Do not add an opaque footer background, duplicate bottom padding, or a web/CSS fade. Verify the final document line and source caret remain reachable above the bar and keyboard. The note's native actions menu uses a compact Pin/Star/Share/Copy group, content/view actions including optional `find`, Open in GitHub, Archive and isolated Delete.

Save labels are assertions about real persistence. In-memory and unsaved states do not claim a local write. Only a confirmed matching remote version is `.savedToGitHub`. Failure messages must be useful, non-sensitive user-facing explanations. Supply retry/review callbacks for recoverable failures. Share callbacks own the unsaved-version choice and secret-link disclosure before presenting the native share sheet.

`PhotoPrivacyNotice(proceed:cancel:)` explains public image storage before the first pick, including for secret gists. Omit `proceed` to show the same notice as help. The app owns per-account acknowledgement and PhotosPicker, without broad library access. Place `PhotoAttachmentShelf(attachments:action:remove:)` above the existing save status in source/preview. Preparing, local durability, waiting for a published note, transfer, uncertainty, reconnect, upload failure and failed local insertion remain distinct. Only a verified upload can offer Insert Here. Retry honors its exact server deadline. The shelf bounds its height and scrolls larger content so multiple photos and accessibility type do not consume the writing viewport. Removal requests require an app-owned confirmation and never imply remote deletion. These components do not upload, insert source or claim an Undo transaction.

`InterfaceFixtures` and SwiftUI previews use synthetic data. The native String Catalog and four-appearance color assets live in the package resource bundle. `scripts/capture-matrix.sh` and `docs/capture-matrix.md` define the shared review workflow. No screen is production-approved until Designer reviews the required Duo evidence.
