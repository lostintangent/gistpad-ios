# Engineering choices

Checked against current Apple documentation on October 23, 2026. The editor/renderer spike is proven and the connected notebook is in M2 integration, not finished-product sign-off.

| Choice | Reason and primary reference |
|---|---|
| Xcode 27.2 SDK, iOS 27.2 minimum | The user confirmed 27.2+ as the product floor, since 27.2 is a security update every device gets. No 27.0 or 27.1 compatibility layout or acceptance gate is required. Standard iPhones remain in scope when running a supported OS. [Duo preparation](https://developer.apple.com/iphone-duo/prepare/) |
| Swift 6 language mode | Strict concurrency is enabled by the language mode. UI state and input stay `@MainActor`. Cross-module edit payloads are value types and `Sendable`. No unchecked concurrency bypasses. [Swift 6 adoption](https://developer.apple.com/documentation/swift/adoptingswift6) |
| `@Observable` document sessions | SwiftUI observes only the state it reads. A session, not a transient view, owns canonical Markdown, generation and the source text view. [Observation in SwiftUI](https://developer.apple.com/documentation/swiftui/managing-model-data-in-your-app) |
| SwiftUI app/navigation/toolbars | Prefer system components and their automatic Liquid Glass, accessibility and Duo behavior. Glass belongs to controls/navigation, not a translucent writing canvas. [Liquid Glass adoption](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass) |
| Native `NavigationSplitView` for Library | One stable sidebar/detail root with native column visibility and compact collapse. Focus hides the sidebar rather than replacing navigation. The available detail width, not hinge angle or device identity, determines whether Edit / Split / Preview can offer two document panes. [NavigationSplitView](https://developer.apple.com/documentation/swiftui/navigationsplitview) |
| Persistent document presentation | The preferred mode is device-local. At 641 pt of detail width, source and live preview share the retained session side by side, leaving 320 pt per pane plus the divider. Narrowing temporarily resolves Split to the compact mode without overwriting its preference, and an active source edit remains in Edit. Source selection, native Undo and the local draft do not belong to a layout branch. The original `ArrangementView` remains in isolated Focus fixtures only. |
| `UITextView(usingTextLayoutManager: true)` via `UIViewRepresentable` | Deliberate UIKit boundary. A plain `TextEditor` does not provide the required attributed highlighting and precise text-system control. TextKit 2 retains selection, undo, IME, dictation, find and system Writing Tools. Never access the legacy layout manager. [TextKit 2 initializer](https://developer.apple.com/documentation/uikit/uitextview/init(usingtextlayoutmanager:)) |
| Event-driven creation focus | New-note and Today creation request `DocumentSession.requestFocusAtEnd()`. The source caret moves immediately; a one-shot first-responder request completes when the retained text view joins a window. No timer, polling or repeat focus on later reattachment. Existing-note navigation does not request it. |
| Fast Today opening | `DailyNotesService.stageToday` reuses the cached owned daily Gist ID, existing durable draft and current cached template/content bytes. The normal path stages through `newFileDraft` without HTTP. Unknown IDs or unavailable required bytes use the existing read-first `openToday(publishIfMissing: false)` path. Starting does not publish. Save uses the ordinary coordinator without a second daily-note publication state machine. |
| Locked publication and lost acknowledgement | Draft SQLite/WAL/SHM files remain `.complete`, and credentials remain `WhenUnlockedThisDeviceOnly`. A background execution lease does not override protected-data access, so publishing after lock is best-effort. On the next opening-time GET, an interrupted known-Gist attempt whose exact source bytes match the remote is acknowledged locally without another PATCH, conflict, source edit or Undo change. Newer local typing remains unpublished. A mismatched or missing remote retains explicit uncertainty. Uncertain first creation can be explicitly authorized again with `confirmNewCreation`, or its unbound local copy discarded with `discardUncertainCreation`. Both check the current generation, account and uncertainty state. Neither guesses a remote match or deletes remote content. Another POST requires the user's deliberate Publish as New Note choice. |
| Local sign-out | Cached restoration is blocked while signing out. Retaining a provider token also requires the same still-persisted account. After the SDK finishes or fails, remove both the account's GitHub provider key and Supabase session key. Attempt both removals even if one fails, and surface credential-store failures. Sign-out does not delete remote content. |
| Quiet remote reads | Opening-time inspection and library refresh use at most three read attempts, with 750-ms and 2-s delays. Parent-task cancellation and superseded presentation stop quietly. Standalone URL cancellation and stale generations retry only while the same account/session remains eligible, then stay quiet if exhausted. Connection failures retry before presenting the shared native footer recovery. Authentication and rate limits are actionable immediately, and a server retry deadline is respected. Retry retains an unresolved problem until actual success. Local persistence failures, uncertain publication, conflicts and uncached first-load failures retain explicit safety recovery rather than a competing footer. Reads never publish or replace source, selection or Undo. Content-free logging records only error types and attempt numbers. |
| Attribute-only syntax highlighting | Never assign replacement strings or attributed strings during SwiftUI updates. Defer decoration while marked text or Writing Tools is active. Code/frontmatter are excluded from Writing Tools. [Writing Tools exclusion delegate](https://developer.apple.com/documentation/uikit/uitextviewdelegate/textview(_:writingtoolsignoredrangesinenclosingrange:)) |
| Surface-owned source underlap | The editor measures vertical safe areas before extending its native representable beneath container chrome. The text view adds only the inset UIKit is missing, updates when native adjusted insets change, and preserves the current passage without editing source or Undo. Keyboard avoidance remains enabled. Geometry tests compare source/caret bounds against real navigation chrome, not only reported scroll insets. |
| Measured comment-thread reveal | The shared inspector measures the selected root in a fully laid-out thread stack and reveals that content coordinate with native `ScrollPosition`. Selection and repeat-reveal revisions request a new measurement. Row reflow, refresh status changes and native viewport frame/inset changes retarget the reveal without timers or fixed inset adjustments. Only a new activation animates; layout maintenance is immediate. The first `.interacting` scroll phase releases that activation's pin, so disclosure, refresh and keyboard changes cannot restore it after manual scrolling. A new passage activation can reveal the same root again. Native regression fixtures use document order different from thread order, offscreen roots, duplicate/overlapping quotes and a controlled real refresh. Assertions check the selected root against actual navigation and composer bounds, not just selected state. |
| Native source token theme | Body, code and frontmatter use shared adaptive ink; caret, accessory actions and task state retain native shared roles. Source-specific dynamic UIColor tokens match the web's GitHub syntax colors in light/dark and their increased-contrast adaptations. Whole headings are body-sized bold, strong/emphasis compose font traits, quotes and HTML have their own color, and links/URLs are underlined. Delimiters inherit their element's color instead of being independently dimmed. Code/frontmatter retain scaled monospace and override inline decorations. Appearance/contrast resolve through dynamic colors without reparsing; only font-metric or Bold Text changes need fresh decoration. See section 6 of `design-system.md`. |
| Complete, plain-text Writing Tools | UIKit owns the inline review, selection and native undo. Temporary suggestions stay in the text view, not canonical source or durable drafts. The completion delegate synchronizes only the final choice as a normal source generation. A rejected/no-op choice creates no source generation. Custom viewport restoration and highlighting pause during the session. Ignored UTF-16 ranges protect frontmatter, variable-length backtick/tilde fences and matching multi-line code spans. [Writing Tools lifecycle](https://developer.apple.com/documentation/uikit/customizing-writing-tools-behavior-for-system-views) |
| One native source keyboard bar | A SwiftUI wrapper keeps the session's persistent TextKit 2 view. The actual text view owns a transparent input accessory containing a native interactive UIGlassEffect capsule, with 12-pt vertical breathing room and five nonoverflowing buttons: Aa, Lists, Insert, Intelligence and Hide Keyboard. Bold/Italic live in Aa. Hide Keyboard is always directly visible. Find and Replace lives in the note menu and the native find shortcuts. Heading, emphasis, list, checklist, link, quote and code actions produce validated Markdown mutations with a final UTF-16 selection and one native Undo. Live notes add Photos to that same Insert menu. Link sheets retain the original document, source and generation and reject stale edits. Formatting is blocked during IME, Writing Tools and read-only access. Actual keyboard/Dynamic Type visual acceptance remains a separate gate. |
| Protected smart typing | The native input delegate routes list Return and URL-over-selection paste through the pure MarkdownTyping engine and the same one-Undo edit path. Ordinary input, marked text, Writing Tools and protected code/frontmatter retain UIKit behavior. The Lists menu and Command-Bracket shortcuts indent/outdent complete lines without guessing source positions. Input failures are surfaced rather than silently applying a fallback edit. |
| `NSRange` and `NSString` at input/bridge boundaries | Deliberate Foundation APIs matching UIKit's UTF-16 coordinates and JavaScript source offsets. Validate bounds, surrogate boundaries, expected source, document identity and generation before editing. Swift `String` remains the canonical source. |
| Byte-exact source equality and validated viewport anchors | Canonically equivalent Unicode strings can have different source bytes, so source-generation and mutation checks compare UTF-8. Reflow restores a source offset, not a raw scroll offset. TextKit 2 can temporarily report estimated caret positions outside the viewport, which must not replace a valid reading anchor. Attribute-only decoration retains that anchor through invalidation, establishes layout and restores its line delta. Reflow does not recapture a different wrapped line as the next anchor. User scrolling and Writing Tools completion establish the new reading position. Hardware latency remains a profiling gate. |
| Source viewport and native chrome | A noninteractive native marker measures the actual safe content rectangle before the scroll view extends beneath container chrome. Convert that rectangle into the retained text view's coordinates rather than adding inherited keyboard/shelf insets to an already shortened editor. Native `UIScrollEdgeElementContainerInteraction` connects the real navigation bar to the source's soft top edge. First-responder caret reveal uses laid-out TextKit geometry after width/height changes. No gradients, fixed bar heights, replacement editor or source mutation. |
| Swift Testing | Unit and package tests use `@Test`, `#expect` and serialized main-actor suites where UIKit requires it. UI automation can use XCTest because Swift Testing does not replace XCUITest. [Swift Testing](https://developer.apple.com/documentation/testing) |
| String Catalogs | `Localizable.xcstrings`, SwiftUI localizable literals and Xcode extraction. Synthetic note content and diagnostic identifiers are not translations. Production UI must not assemble sentences through concatenation. [String Catalogs](https://developer.apple.com/documentation/xcode/localizing-and-varying-text-with-a-string-catalog) |
| Semantic colors and Dynamic Type | Native resolved colors are authoritative. The preview receives the same appearance/font metrics, rather than approximating system colors in CSS. Text styles, contrast, VoiceOver and reduced motion are acceptance criteria. See `design-system.md`. |
| Local Swift packages | Editor, renderer, interface and sync code evolve independently of the app project. The app owns signing and integration. UIKit state stays out of renderer event types. |

## Phase 0 evidence and limits

- Package tests validate UTF-16 mutations, duplicate task positions and protected syntax ranges.
- iOS tests exercise the actual TextKit 2 object across width changes, undo, marked text and rehosting.
- The actual Device Hub Closed/Open/Partially Open/Closed probe passed 322 checkpoints with stable exact source bytes, selection, programmatic marked text, first responder and editor identity. Undo restored the original source. This is simulator evidence, not a real Japanese candidate session.
- Eighteen app tests passed three consecutive runs, including durable generation ordering, newer typing during publication, blocked publication after a local-write failure and lost edit permission. Reflow is checked against the actual next visual line's caret geometry, not a font-metric approximation.
- Every visual surface needs Designer review on Duo cover/open, light/dark and Large/AX3 Dynamic Type before it can be considered production-ready.
- Programmatic marked text is not a real Japanese keyboard candidate session. Simulator posture is not a hardware fold. Device input, Writing Tools and keyboard state are separate remaining gates.
- Authentication, local persistence and cloud sync are not implied by a running editor. Debug captures and test hosts remain explicitly in-memory and isolated from account access. The normal app now uses the live adapter and durable drafts, with a save status acknowledged only after the corresponding store/network result. Real sign-in and the approved scratch-gist round trip remain separate M2 gates.
- No App Store work, CloudKit, custom window activation, hinge gestures or unsupported conditional GitHub writes.

Retained pane accessibility crosses the native representable boundary explicitly through `isNotebookPaneVisible`. Source, Preview and photo controls remain mounted, preserving document identity, selection, composition, Undo and scroll state. Hidden native views set `isHidden` and `accessibilityElementsHidden`, and hidden source/photo targets clear `isAccessibilityElement`. XCUITest's full hierarchy can still list retained hidden UIKit views, so snapshot presence or duplicate identifiers alone does not establish VoiceOver reachability. Native AX flags and `UIWindow.hitTest` exclusion pass in all three modes and the actual capture root. However, XCUITest still reports the hidden editor and Preview text as hittable during mode changes. This accessibility-hit-test discrepancy remains open as t76, not an accepted simulator limitation or VoiceOver pass. A single-pane photo shelf has exactly one hittable, activatable summary. Accessibility Inspector remains an independent VoiceOver check. App-hosted geometry uses native bounds conversion for `UIView` targets rather than a zero virtual `accessibilityFrame`. Real cached-opening identifiers, Search activation and Quick Capture input stay covered by XCUITest.

## Writing Tools checkpoint

The 13 editor package tests pass. Lifecycle-driven iOS checks verify final-choice-only draft persistence, rejected/no-op choices, plain-text output, protected ranges, native Undo/Redo and retained selection. These tests exercise UIKit replacements and delegate callbacks, not generated model output.

The earlier combined frozen run exposed reading-anchor drift after Writing Tools and subsequent reflow. The corrected attribute transaction and retained reflow anchor now pass the complete 13-invocation native continuity suite three consecutive times. Both immediate reflow and reflow after deferred decoration remain within one actual visual line at display-pixel precision, with unchanged source bytes, generation, selection and text-view identity. The separately observed cross-suite initial-keyboard caret failure is not cleared by that reading-only gate.

On the iOS 27.1 Duo simulator (not yet rechecked on 27.2), `UIWritingToolsCoordinator.isWritingToolsAvailable` reports `false`. A real-device accept/reject/rewrite demonstration and system-managed rewrite undo remain hardware gates. The actual-posture probe is a separate check from these programmatic replacements.

## Whole-note on-device intelligence

Ask, Edit and Review use only `SystemLanguageModel.default` over the entire open file. There is no selection scope, tag suggestion, Private Cloud Compute entitlement or other provider. The framework chooses the read-only model variant. Runtime `contextSize` and actual instruction, prompt and schema token counts determine whether a request fits one pass. Longer notes are partitioned without losing source bytes. Ask reads every part, selects source-block IDs and synthesizes with an explicit selected-evidence limitation. App code supplies exact quoted bytes, and original block provenance survives synthesis and hierarchical reduction rather than citing newly joined separators. It fails visibly when evidence cannot be safely combined rather than truncating the note. [Foundation Models](https://developer.apple.com/documentation/foundationmodels), [Context management](https://developer.apple.com/documentation/foundationmodels/managing-the-context-window).

Edit/Review proposals contain exact source quotes, optional disambiguating context, replacements and reasons. App code verifies literal UTF-8 identity and valid UIKit ranges, disables every overlapping or unanchored hunk and reports omissions. Edit requires replacements and applies the accepted set as one native source transaction and Undo. Review comments apply individually; remaining anchors rebase deterministically without another model call. An empty note has one safe insertion anchor. Changed document/session identity, generation or source bytes reject stale Apply, and the workspace closes the sheet when the account changes. Ask source references are mechanically verified before display; generated prose is not independently fact-checked.

Review results live in the sheet's one model, like Ask and Edit. Looking at Review or checking availability never starts generation. Review comments apply or dismiss individually. Closing the sheet drops unresolved suggestions, which matches Ask, Edit and Notes. Daily/local notes use the identical current-file state without a GitHub dependency.

For task edits, a greedy model first chooses the operation kind, including explicit all-complete/all-uncheck, selected state changes, insertion or deletion. Small operation-specific schemas then identify exact task/list IDs and new text. App code supplies tasks and list headings from the existing Markdown parser, excludes fenced code/front matter and computes checkbox changes, insertion into the selected list or removal of only the selected task lines. It does not route by matching English instructions. New tasks are unchecked and retain the list's prefix and line endings. Task IDs remain in document order across budgeted passes. Ordinary text edits still use exact quotes. Instruction-echo replacements, a completely blank result and near-total deletion with only a tiny replacement are rejected before presentation and again before Apply. Meaningful large rewrites and shortening remain allowed and reviewable.

Ask selects supporting source-block IDs before generating its required answer. Empty or whitespace-only output is an error, not successful completion. The engine checks the complete typed answer once for checks for unverified quoted spans, leaked implementation identifiers, third-person reader references and stray HTML. One bounded quality retry is allowed, and content-free rejection categories go to the `Intelligence` log. Source-authored technical identifiers remain valid content. Factual evaluation cases also enforce a 60-word cap independently of model grading. Guidance favors concise second-person paraphrase and distinguishes ranking-based inference from explicit preference statements. These checks do not independently fact-check every paraphrased claim. A small valid answer is not mislabeled as reaching the output limit. Schema/anchor failures, a genuinely empty answer, rejected prose and output limits have distinct recovery copy. Every terminal UI path has an answer, a nonblank recovery reason or an explicit cancellation notice. Timeout, refusal, unavailable-model and context failures leave source untouched.

The sheet is a native `Form` titled with the note's title. The Ask/Edit/Review picker comes first, then the prompt as an always-editable `TextField`. The toolbar holds Close (`role: .close`) and one verb per mode in `.confirmationAction`: Ask, Propose or Review. Tapping it again reruns, and while a request runs the same slot is Stop, with a plain progress row in the form. Citations and suggestions each get their own section, and Apply is a plain row button. Controls carry no tints, so actions take the personal accent. Standard text starts at medium. Accessibility sizes, active generation and Edit/Review results use large. Edit and Review mark changed words locally with native word tokenization and a byte-exact collection difference. Removed text is secondary and struck through, and inserted text uses primary semibold ink with an underline. Neither comparison side normalizes whitespace, punctuation or Unicode, nor interprets source as rendered Markdown. Generation alone never changes source or enters publication. Applied changes follow the ordinary save lifecycle as one complete Undo/Redo. Exact citation navigation is available in editable Source, and read-only Preview explains its missing source-range mapping.

`bash scripts/evaluate-intelligence.sh 10` runs repeatable real-model evaluations on the Mac. Optional gist arguments fetch live inputs read-only into `/tmp`, never the repository. Synthetic fixtures cover front matter, ranked reading sections and multiple task lists. Edits require byte-exact completion/deletion or exactly one unchecked insertion into the right list, with all original bytes preserved. Favorite grading deterministically checks the generated prose's named favorite and competing favorite assertions; a separate greedy model grade is extra evidence, and private prose is retained for human inspection. The floor is 10/10 for each Edit and 9/10 for favorite queries. Judge the Duo's own model by hand on each build. See `Tools/IntelligenceEval/README.md` for the command, rubric, limitations and retrieval paths.
