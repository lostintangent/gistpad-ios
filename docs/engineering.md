# Engineering rules

These rules aren't obvious from reading the code. The toolchain, the iOS 27.2 floor and the test frameworks are in [AGENTS.md](../AGENTS.md). Sync behavior is in [sync.md](sync.md), and how the package keeps it is in the [GistPadSync README](../Packages/GistPadSync/README.md). Visual and interaction rules are in [design.md](design.md). The module map is in [AGENTS.md](../AGENTS.md#module-map).

| Rule | What and why |
|---|---|
| Models own state | `Library`, `FileSession` and `Editor` are `@MainActor` `@Observable` models. Views don't hold source, so a layout change can't lose text, selection or Undo. Don't add `@unchecked Sendable`. The DEBUG `FixtureProtocol` is the only one. [Observation](https://developer.apple.com/documentation/swiftui/managing-model-data-in-your-app) |
| One TextKit 2 view per file | `Editor` owns the source, its generation and one `TextView`, a `UITextView(usingTextLayoutManager: true)`. Never read `layoutManager`, because it drops the view to TextKit 1. The latest `TextViewHost` in a window owns the view, and dismantling an older host never detaches it. [TextKit 2](https://developer.apple.com/documentation/uikit/uitextview/init(usingtextlayoutmanager:)) |
| Both panes stay mounted | `GistScreen` keeps source and Preview mounted in every mode, so switching keeps selection, composition, Undo and scroll. The hidden pane gets zero opacity, no hit testing and `accessibilityHidden`, and `isPaneVisible` hides its UIKit view. |
| Width decides Split | Split needs 641 points of detail width (`LayoutPreferences.allowsSplit`), never a device or hinge check. The mode is a device-local preference. When narrower, an active edit stays in Edit and the Split preference stays. Read-only files are Preview only. |
| Highlighting sets attributes only | `Editor.highlight()` runs 100 ms after an edit with undo registration off, so it never touches characters, selection or Undo. It waits while text is marked or Writing Tools is active (`Editor.isSettled`). |
| Writing Tools sees prose only | `writingToolsBehavior` is `.complete` with `.plainText` results. Code and front matter are excluded (`Syntax.ignoredWritingToolsRanges`). Source doesn't sync during a Writing Tools session, so only the result the user keeps becomes a generation. [Writing Tools](https://developer.apple.com/documentation/uikit/customizing-writing-tools-behavior-for-system-views) |
| Hidden front matter stays in the source | `textContentManager(_:shouldEnumerate:options:)` skips front matter instead of removing it, so bytes, offsets and Undo don't change. Selection, Select All and backspace stop at `Editor.contentStart`. |
| Focus requests fire once | A new gist, or Today opened with `focusesEditor`, gets a `File.editingRequestID`. `FileSession.requestCreationFocus()` turns each ID into one `Editor.requestFocusAtEnd()`, which completes when the text view enters a window, with no timer. Switching to Edit calls `requestFocusAtContentStart()`. |
| Every change is a checked `Edit` | Every programmatic change, from formatting to Intelligence, is an `Edit`: an `NSRange`, the `expected` text and a replacement. `Editor.apply(_:generation:)` rejects a stale generation or mismatched text and makes one Undo step. UTF-16 ranges match UIKit and the Preview bridge. |
| Compare bytes, not strings | Swift `==` treats canonically equivalent strings as equal even when their bytes differ, so source checks use `utf8.elementsEqual` or `sourceEqual`. |
| Smart typing falls back to UIKit | `Typing.edit` continues lists on Return and links a URL pasted over a selection. Code, front matter, marked text and Writing Tools keep native input. A failed edit sets `Editor.inputError` instead of guessing. |
| Reading position is a source offset | Reflow restores a source offset, not a scroll offset. TextKit 2 reports estimated positions, so `rememberReadingAnchor` ignores an anchor far from the viewport's top. |
| The source runs under the bars | `EditorView` ignores the vertical safe areas, and `TextView` adds only the inset UIKit is missing from what the viewport overlay measures. Caret reveal uses laid-out geometry, because TextKit 2's own reveal stops short on long notes. |
| The keyboard bar is an input accessory | `KeyboardBar` is the text view's `inputAccessoryView`, so it moves with the keyboard. Its formatting buttons need `Editor.canFormat`. Its controls are in [design.md](design.md#the-gist-screen). |
| Background publishing is best effort | Leaving the app publishes inside a `BackgroundLease`. The draft store uses complete file protection, so it closes soon after the phone locks. When the lease expires, publishing stops and the drafts wait on the phone for the next launch. |
| Sign-out is local | `Library` locks every open file and waits for local saves before `AccountStore.signOut(accountID:)` runs. Sign-out never publishes, and drafts stay on the phone. |
| Host tests stay out of the way | The `GistPad` scheme sets `GISTPAD_TESTING=1`, so `GistPadApp` doesn't load a library under app-hosted tests. Suites that drive UIKit are `@MainActor` and `.serialized`. |
| Strings live in String Catalogs | User-facing text goes in `GistPad/Localizable.xcstrings` or a package's `Resources/Localizable.xcstrings` with `bundle: .module`. Don't build sentences by concatenation. [String Catalogs](https://developer.apple.com/documentation/xcode/localizing-and-varying-text-with-a-string-catalog) |

## Whole-note on-device intelligence

Ask, Edit and Review use only `SystemLanguageModel.default` over the entire open file. There is no selection scope, tag suggestion, Private Cloud Compute entitlement or other provider. The framework chooses the read-only model variant. Runtime `contextSize` and actual instruction, prompt and schema token counts determine whether a request fits one pass. Longer notes are partitioned without losing source bytes. Ask reads every part, selects source-block IDs and synthesizes with an explicit selected-evidence limitation. App code supplies exact quoted bytes, and original block provenance survives synthesis and hierarchical reduction rather than citing newly joined separators. It fails visibly when evidence cannot be safely combined rather than truncating the note. [Foundation Models](https://developer.apple.com/documentation/foundationmodels), [Context management](https://developer.apple.com/documentation/foundationmodels/managing-the-context-window).

Edit/Review proposals contain exact source quotes, replacements and reasons. Review may add disambiguating context, and an Edit quote must occur once. App code verifies literal UTF-8 identity and valid UIKit ranges, disables every overlapping or unanchored hunk and reports omissions. Edit requires replacements and applies the accepted set as one native source transaction and Undo. Review comments apply individually; remaining anchors rebase deterministically without another model call. An empty note has one safe insertion anchor. Changed document/session identity, generation or source bytes reject stale Apply, and the workspace closes the sheet when the account changes. Ask source references are mechanically verified before display; generated prose is not independently fact-checked.

Review results live in the sheet's one model, like Ask and Edit. Looking at Review or checking availability never starts generation. Review comments apply or dismiss individually. Closing the sheet drops unresolved suggestions, which matches Ask, Edit and Notes. Daily/local notes use the identical current-file state without a GitHub dependency.

For task edits, a greedy model first chooses the operation kind, including explicit all-complete/all-uncheck, checking or unchecking selected tasks, insertion or deletion. Renaming a task is a text edit, so its checkbox stays byte-exact. Small operation-specific schemas then identify exact task/list IDs and new text. App code supplies tasks and list headings from the existing Markdown parser, excludes fenced code/front matter and computes checkbox changes, insertion into the selected list or removal of only the selected task lines. It does not route by matching English instructions. New tasks are unchecked and retain the list's prefix and line endings. Task IDs remain in document order across budgeted passes. Ordinary text edits use exact quotes, and an unchanged quote is dropped. A request mixing a task change with other text is split into its separate edits, and the split names what "that", "it" or "its" refers to when the request names it. Each task edit keeps the whole request's kind, and each text edit runs alone. Instruction-echo replacements, a completely blank result and near-total deletion with only a tiny replacement are rejected before presentation and again before Apply. Meaningful large rewrites and shortening remain allowed and reviewable.

Ask selects supporting source-block IDs before generating its required answer. Empty or whitespace-only output is an error, not successful completion. The engine checks the complete typed answer once for unverified quoted spans, leaked implementation identifiers, third-person reader references, and stray HTML or braces the source doesn't contain. A runaway answer stops at a 384-token response limit, about three times the longest real answer, and is retried once. One bounded quality retry is allowed, and content-free rejection categories go to the `Intelligence` log. Source-authored technical identifiers remain valid content. Factual evaluation cases also enforce a 60-word cap independently of model grading. Guidance favors concise second-person paraphrase and distinguishes ranking-based inference from explicit preference statements. These checks do not independently fact-check every paraphrased claim. A small valid answer is not mislabeled as reaching the output limit. Schema/anchor failures, a genuinely empty answer, rejected prose and output limits have distinct recovery copy. Every terminal UI path has an answer, a nonblank recovery reason or an explicit cancellation notice. Timeout, refusal, unavailable-model and context failures leave source untouched.

The sheet is a native `Form` titled with the note's title. The Ask/Edit/Review picker comes first, then the prompt as an always-editable `TextField`. The toolbar holds Close (`role: .close`) and one verb per mode in `.confirmationAction`: Ask, Propose or Review. Tapping it again reruns, and while a request runs the same slot is Stop, with a plain progress row in the form. Citations and suggestions each get their own section, and Apply is a plain row button. Controls carry no tints, so actions take the personal accent. Standard text starts at medium. Accessibility sizes, active generation and Edit/Review results use large. Edit and Review mark changed words locally with native word tokenization and a byte-exact collection difference. Removed text is secondary and struck through, and inserted text uses primary semibold ink with an underline. Neither comparison side normalizes whitespace, punctuation or Unicode, nor interprets source as rendered Markdown. Generation alone never changes source or enters publication. Applied changes follow the ordinary save lifecycle as one complete Undo/Redo. Exact citation navigation is available in editable Source, and read-only Preview explains its missing source-range mapping.

`bash scripts/evaluate-intelligence.sh 10` runs repeatable real-model evaluations on the Mac. Optional gist arguments fetch live inputs read-only into `/tmp`, never the repository. Synthetic fixtures cover front matter, ranked reading sections and multiple task lists. Edits require byte-exact completion, deletion, text and mixed changes, or exactly one unchecked insertion into the right list, with all original bytes preserved. Favorite grading deterministically checks the generated prose's named favorite and competing favorite assertions; a separate greedy model grade is extra evidence, and private prose is retained for human inspection. The floor is 10/10 for each Edit and 9/10 for favorite queries. Judge the Duo's own model by hand on each build. See `Tools/IntelligenceEval/README.md` for the command, rubric, limitations and retrieval paths.
