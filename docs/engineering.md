# Engineering rules

These rules aren't obvious from reading the code. The toolchain, the iOS 27.2 floor and the test frameworks are in [AGENTS.md](../AGENTS.md). Sync behavior is in [sync.md](sync.md), and how the module keeps it is in the [Sync README](../Sources/Shared/Sync/README.md). Visual and interaction rules are in [design.md](design.md). The module map is in [AGENTS.md](../AGENTS.md#module-map).

| Rule | What and why |
|---|---|
| Models own state | `Library`, `FileSession` and `Editor` are `@MainActor` `@Observable` models. Views don't hold source, so a layout change can't lose text, selection or Undo. Don't add `@unchecked Sendable`. The DEBUG `FixtureProtocol` is the only one. [Observation](https://developer.apple.com/documentation/swiftui/managing-model-data-in-your-app) |
| One TextKit 2 view per file | `Editor` owns the source, its generation and one `TextView`, a `UITextView(usingTextLayoutManager: true)`. Never read `layoutManager`, because it drops the view to TextKit 1. The latest `TextViewHost` in a window owns the view, and dismantling an older host never detaches it. [TextKit 2](https://developer.apple.com/documentation/uikit/uitextview/init(usingtextlayoutmanager:)) |
| Both panes stay mounted | `GistScreen` keeps source and Preview mounted in every mode, so switching keeps selection, composition, Undo and scroll. The hidden pane gets zero opacity, no hit testing and `accessibilityHidden`, and `isPaneVisible` hides its UIKit view. |
| Width decides Split | Split needs 641 points of detail width (`LayoutPreferences.allowsSplit`), never a device or hinge check. The mode is a device-local preference. When narrower, an active edit stays in Edit and the Split preference stays. Read-only files are Preview only. |
| Highlighting sets attributes only | `Editor.highlight()` runs 100 ms after an edit with undo registration off, so it never touches characters, selection or Undo. It waits while text is marked or Writing Tools is active (`Editor.isSettled`). |
| Writing Tools sees prose only | `writingToolsBehavior` is `.complete` with `.plainText` results. Code and front matter are excluded (`Syntax.ignoredWritingToolsRanges`). Source doesn't sync during a Writing Tools session, so only the result the user keeps becomes a generation. [Writing Tools](https://developer.apple.com/documentation/uikit/customizing-writing-tools-behavior-for-system-views) |
| Hidden front matter stays in the source | `textContentManager(_:shouldEnumerate:options:)` skips front matter instead of removing it, so bytes, offsets and Undo don't change. Selection, Select All and backspace stop at `Editor.contentStart`. |
| Focus requests fire once | A new gist, or Today opened with `focusesEditor`, gets a `File.editingRequestID`. `FileSession.requestCreationFocus()` turns each ID into one `Editor.requestFocusAtEnd()`, which completes when the text view enters a window, with no timer. Switching to Edit calls `requestFocusAtContentStart()`. |
| Every change is a checked `Edit` | Every programmatic change, from formatting to Intelligence, is an `Edit`: an `NSRange`, the `expected` text and a replacement. `Editor.apply(_:generation:)` rejects a stale generation or mismatched text and makes one Undo step. UTF-16 ranges match UIKit and the Preview bridge. |
| Compare bytes, not strings | Swift `==` treats canonically equivalent strings as equal even when their bytes differ, so source checks use `utf8.elementsEqual` or `sourceEqual`. |
| Smart typing falls back to UIKit | `Typing.edit` continues lists on Return and links a URL pasted over a selection. Code, front matter, marked text and Writing Tools keep native input. A failed edit sets `Editor.inputError` instead of guessing. |
| Reading position is a source offset | Reflow restores a source offset, not a scroll offset. TextKit 2 reports estimated positions, so `rememberReadingAnchor` ignores an anchor far from the viewport's top. |
| The source runs under the bars | `EditorView` ignores the vertical safe areas, and `TextView` adds only the inset UIKit is missing from what the viewport overlay measures. Caret reveal uses laid-out geometry, because TextKit 2's own reveal stops short on long notes. |
| The keyboard bar is an input accessory | `KeyboardBar` is the text view's `inputAccessoryView`, so it moves with the keyboard. Its formatting buttons need `Editor.canFormat`. Its controls are in [design.md](design.md#the-gist-screen). |
| Background publishing is best effort | Leaving the app publishes inside a `BackgroundLease`. The draft store uses complete file protection, so it closes soon after the phone locks. When the lease expires, publishing stops and the drafts wait on the phone for the next launch. |
| Sign-out is local | `Library` locks every open file and waits for local saves before `AccountStore.signOut(accountID:)` runs. Sign-out never publishes, and drafts stay on the phone. |
| Host tests stay out of the way | The `GistPad` scheme sets `GISTPAD_TESTING=1`, so `GistPadApp` doesn't load a library under app-hosted tests. Suites that drive UIKit are `@MainActor` and `.serialized`. |
| Strings live in String Catalogs | User-facing text goes in `Sources/App/Localizable.xcstrings` or a module's `Resources/Localizable.xcstrings` with `bundle: .module`. Don't build sentences by concatenation. [String Catalogs](https://developer.apple.com/documentation/xcode/localizing-and-varying-text-with-a-string-catalog) |

## Whole-note on-device intelligence

Siri leads for questions about the open note; GistPad Ask remains a private offline option with verified citations and is frozen for feature work. Ask, Edit and Review use only `SystemLanguageModel.default`, with no cloud or third-party model. They see the body, never front matter, even when the note is split. The app preserves original UTF-16 source ranges for citations and exact edit quotes. [Foundation Models](https://developer.apple.com/documentation/foundationmodels), [Context management](https://developer.apple.com/documentation/foundationmodels/managing-the-context-window).

| Observed platform gap | Smallest added step | Evidence and remaining limit |
|---|---|---|
| Metadata reached some model calls. The live note's front matter was 1,459 UTF-16 units. Its old Ask input was about 4,290 tokens, above the Mac's 3,616-token input allowance. | Exclude front matter on every path; compact the numbered block payload and apply ranking guidance only to preference questions. Answer from the entire body when it fits. | Mac AFM 3 Core has a 4,096-token context. The same live input is now about 3,464 tokens. The changes were measured together, so no saving can be assigned to body slicing alone. The Duo's allowance is not measured. |
| Extraction invented block ID 11 for a chunk with only three blocks. A padded live input of about 3,691 tokens still needs extraction. | Constrain IDs to that chunk's range with a generation schema; verify selected IDs and quotes before citing; combine verbatim evidence without replacing its provenance. | The padded live case passed 3/3 on Mac. A note that cannot be combined safely fails visibly rather than truncating or inventing a source. |
| The former Ask schema produced 27 malformed answers ending in `}` among 132 attempts, and no prose appeared before completion. | Stream plain prose; hide incomplete `Sources:` labels; attach exact, verified citation chips only after completion. Retry invalid IDs, unsupported quotation, markup leaks and output-limit failures at most once. | Paired Ask rose from 76/135 to **108/135** (45 cases × 3). Completion p50 fell from 7.85s to 5.00s, while first-visible p50 was 4.86s. Untouched held-out questions rose from 30/39 to 33/39 with no case-level loss; six live variants passed 18/18 on Mac. Generated prose is not independently fact-checked and the earlier Duo error remains unexplained. |
| Whole-note rewrites on full-size notes changed unrelated text or exhausted the context. The old 35-case Edit result had nine real successes and one passing refusal. | Choose a heading and one body block, rewrite that heading's direct content with context, then propose only exact line-diff hunks inside the selected block. Split on actual context overflow, never silently truncate. Keep the existing JSON prompt for short notes. | Build 34 reached **24/35**, with zero `noteTooLong` results and no off-region changes among 27 proposals. Seven cases made no proposal. Untouched short-note held-out cases rose from 15/36 to 21/36 with no per-case loss; switching short notes to raw Markdown had fallen to 9/36. This is a review-before-Apply improvement, not the 10-repeat acceptance floor or a Duo measurement. |
| Task operations needed exact checkbox/list selection rather than a free-form rewrite; mixed task and prose instructions sometimes conflated the two. | Model-classify the requested operation, select constrained task/list IDs and split mixed requests into separate edits. Verify every source quote and selection before proposing. | Exact completion, deletion, insertion, renaming and mixed requests are included in the 35-case Edit matrix. The 24/35 result is for the combined path, not an isolated gain from classification. |

Review displays anchored suggestions without modifying source. Edit changes apply only after the user accepts them, as one native Undo transaction. Ambiguous anchors, stale source or session, instruction echoes, and unsafe near-total deletion reject Apply. Ask checks source IDs and citations but cannot prove every paraphrase true. No model result publishes a note by itself. See [the evaluation rubric](../scripts/intelligence-eval/README.md) for private fixture handling, thresholds and known grading limitations. Editing behavior on the Duo after Build 34 remains unverified.
