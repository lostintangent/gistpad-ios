# Engineering rules

These rules aren't obvious from reading the code. The toolchain, the iOS 27.2 floor and the test frameworks are in [AGENTS.md](../AGENTS.md). Sync behavior is in [sync.md](sync.md), and how the code keeps it is in the [Model](../Sources/Features/Model/README.md) and [Store](../Sources/Shared/Store/README.md) READMEs. Visual and interaction rules are in [design.md](design.md). The module map is in [AGENTS.md](../AGENTS.md#module-map).

| Rule | What and why |
|---|---|
| Models own state | `GistPadModel`, `GistFileEditor` and `MarkdownEditor` are `@Observable` models on the main actor. Views don't hold source, so a layout change can't lose text, selection or Undo. Don't add `@unchecked Sendable`. The DEBUG `FixtureProtocol` is the only one. [Observation](https://developer.apple.com/documentation/swiftui/managing-model-data-in-your-app) |
| The main actor is the default | The app, Editor, Intelligence, Model, Preview, Screens and their tests default to the main actor (`SWIFT_DEFAULT_ACTOR_ISOLATION` and `.defaultIsolation`), as Xcode's app template does, so their declarations don't say `@MainActor`. Code that runs elsewhere says `nonisolated` or `@concurrent`. Store, Comments, Markdown, Appearance and Platform stay nonisolated, because their actors, the system and the widget call them off the main actor. The widget follows Xcode's template, and the UI tests stay nonisolated because `XCTestCase`'s overrides can't move to the main actor. Every target takes approachable concurrency, since modules that disagree mangle async function types differently and fail to link. [SE-0466](https://github.com/swiftlang/swift-evolution/blob/main/proposals/0466-control-default-actor-isolation.md) |
| One TextKit 2 view per file | `MarkdownEditor` owns the note's `MarkdownDocument`, its generation and one `TextView`, a `UITextView(usingTextLayoutManager: true)`. Never read `layoutManager`, because it drops the view to TextKit 1. The latest `TextViewHost` in a window owns the view, and dismantling an older host never detaches it. [TextKit 2](https://developer.apple.com/documentation/uikit/uitextview/init(usingtextlayoutmanager:)) |
| Both panes stay mounted | `GistScreen` keeps source and Preview mounted in every mode, so switching keeps selection, composition, Undo and scroll. The hidden pane gets zero opacity, no hit testing and `accessibilityHidden`, and `isPaneVisible` hides its UIKit view. |
| Width decides Split | Split needs 641 points of detail width (`LayoutPreferences.allowsSplit`), never a device or hinge check. The mode is a device-local preference. When narrower, an active edit stays in Edit and the Split preference stays. Read-only files are Preview only. |
| Highlighting sets attributes only | `MarkdownEditor.highlight()` paints the document's spans and the `CommentHighlighter`'s pills through `TextView.updateAttributes` once an edit lands, in the same turn, with undo registration off, so it never touches characters, selection or Undo. It waits while text is marked or Writing Tools is active (`MarkdownEditor.isSettled`). Comment pills stay drawn until the next matching pass, rather than clearing on each keystroke. |
| Writing Tools sees prose only | `writingToolsBehavior` is `.complete` with `.plainText` results. Code and front matter are excluded (`MarkdownDocument.protectedRanges(in:)`). Source doesn't sync during a Writing Tools session, so only the result the user keeps becomes a generation. [Writing Tools](https://developer.apple.com/documentation/uikit/customizing-writing-tools-behavior-for-system-views) |
| Hidden front matter stays in the source | `textContentManager(_:shouldEnumerate:options:)` skips front matter instead of removing it, so bytes, offsets and Undo don't change. Selection, Select All and backspace stop at `MarkdownDocument.contentStart`. |
| Focus requests fire once | Presenting a new gist or Today puts its `GistFileEditor` in Edit and calls `MarkdownEditor.requestFocusAtEnd()` once. The request completes when the text view enters a window, with no timer, and the root keeps Edit while it's pending. Switching to Edit only shows the source, and the keyboard waits for a tap. Beginning to edit doesn't reveal the caret, because UIKit places a tap's caret after it. |
| Every change is a `MarkdownEdit` | Every programmatic change, from formatting to Intelligence, is a `MarkdownEdit` made by an `edit(…)` method on the `MarkdownDocument` it changes. `MarkdownEditor.apply(_:)` makes one Undo step. It throws `MarkdownEdit.Failure.unsettled` during composition or Writing Tools and `.changed` when the editor no longer shows the edit's document, and each failure carries the sentence the user sees. UTF-16 ranges match UIKit and the Preview bridge. [Markdown](../Sources/Shared/Markdown/README.md) |
| Compare bytes, not strings | Swift `==` treats canonically equivalent strings as equal even when their bytes differ, so source checks use `utf8.elementsEqual`, and `MarkdownDocument`'s `==` compares code units. |
| Smart typing falls back to UIKit | `MarkdownDocument.edit(typing:over:)` continues lists on Return, pairs `()`, `[]` and `{}` from one table, and links a URL pasted over a selection. Code, front matter, marked text and Writing Tools keep native input. A failed edit sets `MarkdownEditor.inputError` instead of guessing. |
| Reading position is a source offset | Reflow restores a source offset, not a scroll offset. TextKit 2 reports estimated positions, so `rememberReadingAnchor` ignores an anchor far from the viewport's top. |
| The source runs under the bars | `MarkdownEditorView` ignores the vertical safe areas. UIKit insets the source below the bars, and `TextView` adds only the keyboard and its bar, which its host reads from its keyboard layout guide. Caret reveal uses laid-out geometry, because TextKit 2's own reveal stops short on long notes. |
| The keyboard bar is an input accessory | `KeyboardBar` is the text view's `inputAccessoryView`, so it moves with the keyboard. Its formatting buttons need `MarkdownEditor.canFormat`. Its controls are in [design.md](design.md#the-gist-screen). |
| Background publishing is best effort | Leaving the app publishes inside a `BackgroundLease`. The app's `default-data-protection` entitlement gives the draft store complete file protection, so it closes soon after the phone locks. When the lease expires, publishing stops, the note shows Saved on iPhone, and the next publish checks GitHub for the cut-off attempt before sending again. |
| Sign-out is local | `GistPadModel` locks every open file and waits for local saves before `GistPadAccountStore.signOut(accountID:)` runs. Sign-out never publishes, and drafts stay on the phone. |
| Host tests stay out of the way | The `GistPad` scheme sets `GISTPAD_TESTING=1`, so `GistPadApp` doesn't load a library under app-hosted tests. Suites that drive UIKit are `.serialized`. |
| One simulator suite | The `GistPad` scheme also runs the iOS package tests, which is why `GistPad.xcworkspace` exists. `GistPadTests` links no package products and reaches the modules through its host app, so test builds link them statically, as shipping builds do. Linking one into the test bundle turns them all into frameworks, where the system can't find GistPad's intents, and every Spotlight update then stalls the test process for about 40 seconds. The simulator's keyboard outlives each test process and may be the software keyboard or a hardware keyboard's bar, so window tests check the caret against whichever keyboard frame settles. |
| Strings live in String Catalogs | User-facing text goes in `Sources/App/Localizable.xcstrings` or a module's `Resources/Localizable.xcstrings` with `bundle: .module`. Don't build sentences by concatenation. [String Catalogs](https://developer.apple.com/documentation/xcode/localizing-and-varying-text-with-a-string-catalog) |

## Shared words

Every module uses one word for each of these, and the UI's words follow design.md's [Words](design.md#words).

| Noun | Means | Type |
|---|---|---|
| Account | A signed-in GitHub identity and its preferences | `GistPadAccount` |
| Preferences | The account's settings, synced through Supabase metadata | `GistPadPreferences` |
| Gist | A GitHub gist | `Gist` |
| File | One Markdown file in a gist | `GistFile` |
| Draft | This iPhone's saved copy of a file, waiting to publish | `GistFileDraft` |
| Daily note | A dated file in the daily gist | `DailyNote` |
| Library | Your gists, as the list shows them | `LibraryState` |
| Tag | A named, colored label on a gist | `Tag` |
| Comment | A GitHub gist comment, optionally quoting a passage | `GistComment` |
| Editor and Preview | The two ways to show an open file | `MarkdownEditor`, `MarkdownPreviewView` |
| Document | A note's Markdown, read once: its front matter, body, blocks and spans | `MarkdownDocument` |
| Edit | A change made from one document, applied as one Undo step | `MarkdownEdit` |
| Proposal | What Edit or Review returns for a note: changes or suggestions, each quoting its passage | `Proposal` |
| Suggestion | One of Review's notes on a passage. It offers a replacement only when the fix is clear, and nothing changes until you apply it. | `Proposal.Change`, like Edit's changes |
| Failure | Something you asked for that didn't happen: one true sentence and the one button that may fix it | `Failure` |
| GitHub status | Whether the list or the open note is checking GitHub or couldn't, shown in the toolbar | `GitHubStatus` |

The verbs are **save** (to this iPhone), **publish** (to GitHub), **refresh** (read GitHub with `refresh()`, which the UI calls checking for changes) and **conflict** (GitHub changed underneath a draft), with no "land" or "remote": a file `isLocked` while a change you didn't type goes in, and GitHub's side is `github`.

## Whole-note on-device intelligence

Siri leads for questions about the open note; GistPad Ask remains a private offline option with verified citations and is frozen for feature work. Ask, Edit and Review use only `SystemLanguageModel.default`, with no cloud or third-party model. They see the body, never front matter, even when the note is split. `MarkdownDocument`'s `blocks` and `taskMarkers` supply shared UTF-16 blocks and task markers for Ask citations, Edit scope and Review's move check. The app preserves original source ranges for citations and exact edit quotes. Each input is counted with `tokenCount(for:)` over the same instructions and prompt entries the session sends, which matched reported usage exactly on Mac, so no framing reserve is held back. Switching to it in Build 60 left all 35 Edit outputs unchanged. [Foundation Models](https://developer.apple.com/documentation/foundationmodels), [Context management](https://developer.apple.com/documentation/foundationmodels/managing-the-context-window).

| Observed platform gap | Smallest added step | Evidence and remaining limit |
|---|---|---|
| Metadata reached some model calls. The live note's front matter was 1,459 UTF-16 units. Its old Ask input was about 4,290 tokens, above the Mac's 3,712-token input allowance. | Exclude front matter on every path; compact the numbered block payload and apply ranking guidance only to preference questions. Answer from the entire body when it fits. | Mac AFM 3 Core has a 4,096-token context. The same live input is now about 3,464 tokens. The changes were measured together, so no saving can be assigned to body slicing alone. The Duo's allowance is not measured. |
| Extraction invented block ID 11 for a chunk with only three blocks. Inputs above the 3,712-token allowance still need extraction. | Constrain IDs to that chunk's range with a generation schema; verify selected IDs and quotes before citing; combine verbatim evidence without replacing its provenance. | A padded live case near the allowance passed 3/3 on Mac through extraction. A note that cannot be combined safely fails visibly rather than truncating or inventing a source. |
| The former Ask schema produced 27 malformed answers ending in `}` among 132 attempts, and no prose appeared before completion. | Stream plain prose; hide incomplete `Sources:` labels; attach exact, verified citation chips only after completion. Retry invalid IDs, unsupported quotation, markup leaks and output-limit failures at most once. | Paired Ask rose from 76/135 to **108/135** (45 cases × 3). Completion p50 fell from 7.85s to 5.00s, while first-visible p50 was 4.86s. Untouched held-out questions rose from 30/39 to 33/39 with no case-level loss; six live variants passed 18/18 on Mac. Build 48 dropped the comparison and name-only prompt branches and the second token count after streaming. Ask went from 90/117 to 88/117 (39 cases × 3), with the two lost runs on count questions whose prompts were unchanged, and no output-limit failures either way. The three name-only cases fail exact grading in both, though every answer names the right item. A 16-token stream reports live usage per snapshot and still throws `responseTooLarge`. Generated prose is not independently fact-checked and the earlier Duo error remains unexplained. |
| Whole-note rewrites on full-size notes changed unrelated text or exhausted the context. The old 35-case Edit result had nine real successes and one passing refusal. | Choose a heading and one body block, rewrite that heading's direct content with context, then propose only exact line-diff hunks inside the selected block. Split on actual context overflow, never silently truncate. Keep the existing JSON prompt for short notes. | Build 34 reached **24/35**, with zero `noteTooLong` results and no off-region changes among 27 proposals. Seven cases made no proposal. Untouched short-note held-out cases rose from 15/36 to 21/36 with no per-case loss; switching short notes to raw Markdown had fallen to 9/36. This is a review-before-Apply improvement, not the 10-repeat acceptance floor or a Duo measurement. |
| Task operations needed exact checkbox/list selection rather than a free-form rewrite; mixed task and prose instructions sometimes conflated the two. | Model-classify the requested operation, select constrained task/list IDs and split mixed requests into separate edits. Verify every source quote and selection before proposing. | Exact completion, deletion, insertion, renaming and mixed requests are included in the 35-case Edit matrix. The 24/35 result is for the combined path, not an isolated gain from classification. |
| AFM Core misread where some English requests apply. It sent section, summary and table additions to task edits, and picked wrong targets for "at the end" and table rows. | Route "at the end" and "add … row … table" requests directly. Other wording and languages use model selection. | Without any routes, full-size Edit fell from 24/35 to 19/35 and proposed off-region changes. A language-neutral placement classifier reached 15/35. Model-extracted moves reached 21/35 and took 22% longer. Both were rejected. Build 48 cut the routes that each served one case: "after the introduction", "after *heading*", "into a list", a named "paragraph about …" deletion, a named `move … from … to …` list move and a dollar amount placed in a price column. Full-size Edit went from 31/35 to **26/35** in one paired run, losing exactly those five. Four now make no proposal and the move is rejected before Apply. No other case changed. Non-English positional requests rely on weaker model selection. |
| When AFM Core rewrote a whole section, it often left the selected block alone, so seven full-size requests made no proposal. Asked to revise just the block, it invented headings and code fences around it. | For English shorten, translate, "turn … into a list", "add a summary under … heading" and "add … row … table" requests, revise only the selected block with its section as context, move a pure insertion the model placed elsewhere to just after the block, and check the reply's Markdown shape. | Full-size Edit rose from 24/35 to **31/35** in one run, fixing all seven and losing none. Short-note held-out stayed at 21/36 with identical per-case results. A generic block prompt with the same section context stayed at 24/35, and a block-only fallback proposed off-region edits, so both were rejected. Other wording and languages still rely on the section rewrite, which can propose nothing. |

Review displays anchored suggestions without modifying source. Edit changes apply only after the user accepts them, as one native Undo transaction. Ambiguous anchors, stale source or session, instruction echoes, and unsafe near-total deletion reject Apply. Ask checks source IDs and citations but cannot prove every paraphrase true. No model result publishes a note by itself. See [the evaluation rubric](../scripts/intelligence-eval/README.md) for private fixture handling, thresholds and known grading limitations. Editing behavior on the Duo after Build 34 remains unverified.
