# Engineering rules

These rules aren't obvious from reading the code. The toolchain, the iOS 27.2 floor and the test frameworks are in [AGENTS.md](../AGENTS.md). Sync behavior is in [sync.md](sync.md), and how the module keeps it is in the [Sync README](../Sources/Shared/Sync/README.md). Visual and interaction rules are in [design.md](design.md). The module map is in [AGENTS.md](../AGENTS.md#module-map).

| Rule | What and why |
|---|---|
| Models own state | `Library`, `FileSession` and `Editor` are `@MainActor` `@Observable` models. Views don't hold source, so a layout change can't lose text, selection or Undo. Don't add `@unchecked Sendable`. The DEBUG `FixtureProtocol` is the only one. [Observation](https://developer.apple.com/documentation/swiftui/managing-model-data-in-your-app) |
| One TextKit 2 view per file | `Editor` owns the source, its generation and one `TextView`, a `UITextView(usingTextLayoutManager: true)`. Never read `layoutManager`, because it drops the view to TextKit 1. The latest `TextViewHost` in a window owns the view, and dismantling an older host never detaches it. [TextKit 2](https://developer.apple.com/documentation/uikit/uitextview/init(usingtextlayoutmanager:)) |
| Both panes stay mounted | `GistScreen` keeps source and Preview mounted in every mode, so switching keeps selection, composition, Undo and scroll. The hidden pane gets zero opacity, no hit testing and `accessibilityHidden`, and `isPaneVisible` hides its UIKit view. |
| Width decides Split | Split needs 641 points of detail width (`LayoutPreferences.allowsSplit`), never a device or hinge check. The mode is a device-local preference. When narrower, an active edit stays in Edit and the Split preference stays. Read-only files are Preview only. |
| Highlighting sets attributes only | `Editor.highlight()` runs 100 ms after an edit with undo registration off, so it never touches characters, selection or Undo. It waits while text is marked or Writing Tools is active (`Editor.isSettled`). |
| Writing Tools sees prose only | `writingToolsBehavior` is `.complete` with `.plainText` results. Code and front matter are excluded (`Syntax.ignoredWritingToolsRanges`). Source doesn't sync during a Writing Tools session, so only the result the user keeps becomes a generation. [Writing Tools](https://developer.apple.com/documentation/uikit/customizing-writing-tools-behavior-for-system-views) |
| Hidden front matter stays in the source | `textContentManager(_:shouldEnumerate:options:)` skips front matter instead of removing it, so bytes, offsets and Undo don't change. Selection, Select All and backspace stop at `Editor.contentStart`. |
| Focus requests fire once | A new gist, or Today opened with `focusesEditor`, gets a `File.editingRequestID`. `FileSession.requestCreationFocus()` turns each ID into one `Editor.requestFocusAtEnd()`, which completes when the text view enters a window, with no timer. Switching to Edit calls `requestFocusAtContentStart()`. |
| Every change is a checked `Edit` | Every programmatic change, from formatting to Intelligence, is an `Edit`: an `NSRange`, the `expected` text and a replacement. `Editor.apply(_:generation:)` rejects a stale generation or mismatched text and makes one Undo step. UTF-16 ranges match UIKit and the Preview bridge. |
| Compare bytes, not strings | Swift `==` treats canonically equivalent strings as equal even when their bytes differ, so source checks use `utf8.elementsEqual` or `sourceEqual`. |
| Smart typing falls back to UIKit | `Typing.edit` continues lists on Return and links a URL pasted over a selection. Code, front matter, marked text and Writing Tools keep native input. A failed edit sets `Editor.inputError` instead of guessing. |
| Reading position is a source offset | Reflow restores a source offset, not a scroll offset. TextKit 2 reports estimated positions, so `rememberReadingAnchor` ignores an anchor far from the viewport's top. |
| The source runs under the bars | `EditorView` ignores the vertical safe areas, and `TextView` adds only the inset UIKit is missing from what the viewport overlay measures. Caret reveal uses laid-out geometry, because TextKit 2's own reveal stops short on long notes. |
| The keyboard bar is an input accessory | `KeyboardBar` is the text view's `inputAccessoryView`, so it moves with the keyboard. Its formatting buttons need `Editor.canFormat`. Its controls are in [design.md](design.md#the-gist-screen). |
| Background publishing is best effort | Leaving the app publishes inside a `BackgroundLease`. The draft store uses complete file protection, so it closes soon after the phone locks. When the lease expires, publishing stops and the drafts wait on the phone for the next launch. |
| Sign-out is local | `Library` locks every open file and waits for local saves before `AccountStore.signOut(accountID:)` runs. Sign-out never publishes, and drafts stay on the phone. |
| Host tests stay out of the way | The `GistPad` scheme sets `GISTPAD_TESTING=1`, so `GistPadApp` doesn't load a library under app-hosted tests. Suites that drive UIKit are `@MainActor` and `.serialized`. |
| Strings live in String Catalogs | User-facing text goes in `Sources/App/Localizable.xcstrings` or a module's `Resources/Localizable.xcstrings` with `bundle: .module`. Don't build sentences by concatenation. [String Catalogs](https://developer.apple.com/documentation/xcode/localizing-and-varying-text-with-a-string-catalog) |

## Whole-note on-device intelligence

Ask, Edit and Review use only `SystemLanguageModel.default` over the open note's body. Front matter remains in the source file but never goes to the model, including on chunked calls; verified quotes retain their original UTF-16 ranges for Show in File. There is no selection scope, tag suggestion, Private Cloud Compute entitlement or other provider. The framework chooses the read-only model variant. Runtime `contextSize` and actual instruction, prompt and schema token counts determine whether a request fits one pass. A fitting Ask answers from the complete body without a separate retrieval call. Longer notes are partitioned without losing source bytes; Ask reads every part, selects source-block IDs constrained to the IDs in that chunk, and synthesizes with an explicit selected-evidence limitation. App code supplies exact quoted bytes, and original block provenance survives synthesis and hierarchical reduction rather than citing newly joined separators. It fails visibly when evidence cannot be safely combined rather than truncating the note. [Foundation Models](https://developer.apple.com/documentation/foundationmodels), [Context management](https://developer.apple.com/documentation/foundationmodels/managing-the-context-window).

The platform gaps are measured against the saved pre-change executable, not an idealized cloud model. On this Mac, AFM 3 Core reports a 4,096-token context; Ask reserves 384 output tokens and 96 framing tokens, leaving **3,616 input tokens**. These changes were evaluated together, so no row attributes the aggregate quality or latency gain to one isolated change.

| Gap observed | Smallest added step | Evidence and remaining limit |
|---|---|---|
| Metadata could reach Ask/Review and was sent on some Edit paths. The live note's front matter alone was 1,459 UTF-16 units (226 words). | Pass only body bytes to every model call, including chunks, while retaining absolute source ranges for verified quotations and edits. | Tests check that metadata cannot reach Ask, Edit or Review and cannot appear as a citation. This was combined with prompt and block changes; token savings cannot be assigned to body slicing alone. |
| The live note's old Ask input was about 4,290 tokens, above the 3,616-token allowance, forcing extraction before answering. | Compact the source-block payload and conditional question guidance so a fitting body uses one answer pass. Constrain extraction IDs to each chunk when it does not fit. | Current live input is about 3,464 and answers in one pass; a padded 3,691-token copy still extracts and passed 3/3. Earlier extraction invented ID 11 for a three-block chunk; schema-constrained IDs and app-side verification prevent citing that phantom block. The phone's model and allowance remain unmeasured. |
| The old guided answer schema produced 27 malformed answers ending in `}` among the original 132 attempts, and Ask had no visible prose until completion. | Stream ordinary prose, parse final source IDs, show partial prose without partial source labels, and add exact app-verified citation chips only at completion. Reject invalid IDs, unsupported quoted spans and leaking implementation markers with one bounded retry. | On paired 45-case runs, pass rate rose from 76/135 to 108/135 and completion p50 fell from 7.85s to 5.00s. First visible p50 is 4.86s, close to completion, so this is not yet a large time-to-first-word gain. The old path did not publish partial prose. |

General ranking rules also contaminated unrelated questions. | Apply preference guidance only to preference questions, require an explicit first-sentence answer, prefer a stated favorite over ranking inference, and recognize bracketed or plain final source labels. | The final six live questions passed 18/18 on the Mac, including exact phone wording and a padded extraction variant. Untouched held-out questions improved from 30/39 to 33/39 with no case-level regression. The device's earlier Billy Bat response remains unexplained; neither this result nor citation verification proves generated prose is true. |

Edit/Review proposals contain exact source quotes, replacements and reasons. Review may add disambiguating context, and an Edit quote must occur once. App code verifies literal UTF-8 identity and valid UIKit ranges, disables every overlapping or unanchored hunk and reports omissions. Edit requires replacements and applies the accepted set as one native source transaction and Undo. Review comments apply individually; remaining anchors rebase deterministically without another model call. An empty note has one safe insertion anchor. Changed document/session identity, generation or source bytes reject stale Apply, and the workspace closes the sheet when the account changes. Ask source references are mechanically verified before display; generated prose is not independently fact-checked.

Review results live in the sheet's one model, like Ask and Edit. Looking at Review or checking availability never starts generation. Review comments apply or dismiss individually. Closing the sheet drops unresolved suggestions, which matches Ask, Edit and Notes. Daily/local notes use the identical current-file state without a GitHub dependency.

For task edits, a greedy model first chooses the operation kind, including explicit all-complete/all-uncheck, checking or unchecking selected tasks, insertion or deletion. Renaming a task is a text edit, so its checkbox stays byte-exact. Small operation-specific schemas then identify exact task/list IDs and new text. App code supplies tasks and list headings from the existing Markdown parser, excludes fenced code/front matter and computes checkbox changes, insertion into the selected list or removal of only the selected task lines. Routine task operations are model-classified, not routed by English task keywords; requests explicitly for a paragraph, summary, section, table or intro without task terminology skip that classifier because it mislabeled document additions as new checkboxes. New tasks are unchecked and retain the list's prefix and line endings. Task IDs remain in document order across budgeted passes. Ordinary text edits use exact quotes, and an unchanged quote is dropped. A request mixing a task change with other text is split into its separate edits, and the split names what "that", "it" or "its" refers to when the request names it. Each task edit keeps the whole request's kind, and each text edit runs alone. Instruction-echo replacements, a completely blank result and near-total deletion with only a tiny replacement are rejected before presentation and again before Apply. Meaningful large rewrites and shortening remain allowed and reviewable.

An oversized text edit uses an ID-constrained Markdown outline with small previews of each heading's own content to select a section before splitting the note. Unique heading names, a uniquely referenced paragraph and explicit positions such as under the title, after the introduction or at the end can anchor selection without a model call. An ID-constrained block list otherwise selects one block directly under that heading. The model rewrites the section's own content as raw Markdown for context, but only changed hunks wholly within the selected block can reach the review. The existing line diff and exact UTF-16 anchors splice those proposed changes into the original file. If the section cannot fit in one reply, only the selected block is rewritten. A trial retrying unchanged section proposals against an isolated block produced three off-region proposals without a task success, so no-change returns visibly rather than taking that fallback. Actual context overflow still splits and retries rather than truncating the source. Whole short-note rewrites retain their shipped JSON input: on 12 untouched held-out cases repeated three times, changing those to raw input reduced passes from 15/36 to 9/36. Sections and blocks can still be selected incorrectly, so the user must inspect the review before Apply. A unique named English `move … from … to …` list item moves its exact line between the identified headings without a model call. Ambiguous moves remain model-generated. Apply requires exactly one intact item under a different heading and retains the old heading, rejecting a missing, duplicated or incomplete move.

Ask streams plain prose before its final source IDs are parsed. The sheet shows verified quotation chips only after completion, strips source labels from partial prose and clears unfinished text on failure or cancellation. Empty or whitespace-only output is an error, not successful completion. The engine checks the completed answer for unverified quoted spans, leaked implementation identifiers, third-person reader references, and HTML or braces the source doesn't contain. Source IDs must exist in the body blocks; an invalid ID gets one bounded retry, never a guessed citation. A runaway answer stops at a 384-token response limit and is retried once. One bounded quality retry is allowed, and content-free rejection categories go to the `Intelligence` log. Source-authored technical identifiers remain valid content. Factual evaluation cases also enforce a 60-word cap independently of model grading. Guidance favors concise paraphrase, applies preference/ranking rules only to preference questions, and distinguishes ranking-based inference from explicit statements. These checks do not independently fact-check every paraphrased claim. A small valid answer is not mislabeled as reaching the output limit. Schema/anchor failures, a genuinely empty answer, rejected prose and output limits have distinct recovery copy. Every terminal UI path has an answer, a nonblank recovery reason or an explicit cancellation notice. Timeout, refusal, unavailable-model and context failures leave source untouched.

The sheet is a native `Form` titled with the note's title. The Ask/Edit/Review picker comes first, then the prompt as an always-editable `TextField`. The toolbar holds Close (`role: .close`) and one verb per mode in `.confirmationAction`: Ask, Propose or Review. Tapping it again reruns, and while a request runs the same slot is Stop, with a plain progress row in the form. Citations and suggestions each get their own section, and Apply is a plain row button. Controls carry no tints, so actions take the personal accent. Standard text starts at medium. Accessibility sizes, active generation and Edit/Review results use large. Edit and Review mark changed words locally with native word tokenization and a byte-exact collection difference. Removed text is secondary and struck through, and inserted text uses primary semibold ink with an underline. Neither comparison side normalizes whitespace, punctuation or Unicode, nor interprets source as rendered Markdown. Generation alone never changes source or enters publication. Applied changes follow the ordinary save lifecycle as one complete Undo/Redo. Exact citation navigation is available in editable Source, and read-only Preview explains its missing source-range mapping.

`bash scripts/evaluate-intelligence.sh 10` runs repeatable real-model evaluations on the Mac. Optional gist arguments fetch live inputs read-only into `/tmp`, never the repository. Five full-size synthetic fixtures provide 39 Ask and 35 Edit questions, plus six live Manga Ask variants in the paired comparison. Edits require byte-exact completion, deletion, text and mixed changes, or exactly one unchecked insertion into the right list, with all original bytes preserved. Favorite grading deterministically checks the generated prose's named favorite and competing favorite assertions; a separate greedy model grade is extra evidence, and private prose is retained for human inspection. The floor is 10/10 for each Edit and 9/10 for favorite queries.

The original 35-case Edit result had nine genuine successes; its tenth passing case expected a `noteTooLong` refusal. The current single-pass AFM 3 Core result is 24/35, retaining all nine, with zero `noteTooLong` and a 4.86-second median to a proposed diff across 27 proposals. None of those 27 revisions changed lines outside the requested region. Seven cases returned no applicable change, one fixed only part of the grammar, one rejected a changed title, one produced English heading/prose for a Japanese paragraph request, and one moved an intact item to the right section but failed the evaluator's exact insertion-position expectation. On 12 untouched short-note held-out cases repeated three times, the retained whole-note JSON path passed 21/36 versus its earlier 15/36. All five baseline-passing cases stayed 3/3; two more became 3/3. Its nine off-region failures are the same three cases that failed off-region on every baseline attempt, and the baseline had 18 such failures in six cases. The full-size result remains below the eval's 10-repeat acceptance floor. Build 34 is planned to carry it as a measured, review-before-Apply improvement, not a proof of correctness on the Duo. Ask's last paired comparison passed 108/135; its remaining synthetic misses are on hold while Siri's note-context phone test is pending. See `scripts/intelligence-eval/README.md` for the command, rubric, limitations and retrieval paths.
